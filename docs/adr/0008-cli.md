# ADR-0008. CLI `forest`: вхід через браузер, токен і клієнт API

- Статус: прийнято
- Дата: 2026-10-09

## Контекст

Панель — не єдиний спосіб керувати системою: деплой зі скрипта, перегляд логів у терміналі по SSH, CI. Для цього потрібен CLI, що покриває майже все, що вміє панель. Він автентифікується персональним API-токеном (ADR-0007). Вставляти токен вручну незручно: його треба створити в панелі, скопіювати, не загубити. CLI має вміти отримати токен сам.

Розглянуті способи входу:

1. **Пароль у терміналі.** CLI обмінює логін і пароль на токен. Не працює для passkeys і входу через Discord, а пароль проходить через ще одну програму.
2. **Loopback-редирект із токеном в адресі** (як `gh auth login --web` у старих версіях). Токен потрапляє в історію браузера; не працює по SSH.
3. **Device authorization flow (RFC 8628)** (обрано) із loopback-сигналом: CLI отримує одноразовий код, людина підтверджує його в панелі будь-яким способом входу, CLI забирає токен опитуванням. Працює й по SSH (`--device`), а локально браузер одразу будить CLI через `127.0.0.1`.

## Рішення

### Потік входу

1. CLI: `POST /api/cli/authorizations` з назвою клієнта й хоста. ЦА повертає `deviceCode` (32 випадкові байти, лише для CLI), `userCode` (8 символів без схожих літер, як код прив'язки Discord), шлях сторінки панелі, строк (10 хв) і інтервал опитування (5 с). Обидва коди зберігаються хешами (`CliAuthorization`).
2. Локально CLI слухає `127.0.0.1:<випадковий порт>` і відкриває `<адреса сервера>/cli/authorize?code=<userCode>&port=<порт>`. З `--device` CLI лише друкує адресу `/cli/device` і код.
3. Людина входить у панель (паролем, passkey, Discord — будь-як), бачить клієнт, хост, IP запиту й код для звірки з терміналом, обирає обмеження токена (ті самі, що на екрані «API-токени») і дозволяє або відхиляє. Рішення приймає лише сесія, не токен (`GetSignedInUserAsync`).
4. Після рішення панель переводить браузер на `http://127.0.0.1:<порт>/done?result=…`: це лише сигнал «час опитати», без жодного секрету. Порт панель бере з адреси, а хост завжди `127.0.0.1`, тож перенаправити браузер кудись іще сторінка не може.
5. CLI: `POST /api/cli/token` з `deviceCode` → `Pending` / `SlowDown` / `Approved` (з токеном) / `Denied` / `Expired`. **Токен створюється лише в цю мить** і повертається один раз; у базі між підтвердженням і видачею лежать лише обрані обмеження, а не токен. Невідомий код — `Expired`, як і прострочений.

Захист: ендпоінти без автентифікації й ті, що приймають короткий `userCode`, мають ліміт запитів на адресу (`RateLimiter` ASP.NET Core: 10 запусків, 30 опитувань і 20 звернень до коду на хвилину); відкритих запитів у системі — не більше 500, прострочені видаляються під час нових. Відома слабкість device flow — фішинг (зловмисник надсилає своє посилання): сторінка показує хост, адресу й код і прямо просить відхилити запит, якого людина не запускала.

### Клієнт

- **.NET 10 + System.CommandLine, NativeAOT**: одна мова з рештою бекенду, один бінарник без рантайму (linux/win/mac, x64/arm64). Go чи TypeScript означали б ще одну мову й CI-job.
- **Клієнт API генерує Kiota** із закоміченого OpenAPI-документа ЦА, як `schema.gen.ts` для панелі; CI перевіряє, що він актуальний. Kiota сумісна з AOT і підтримує OpenAPI 3.1, який генерує ASP.NET Core 10. Згенеровані моделі nullable й mutable, тож CLI працює з ними через власний адаптер (`IForestApi`), а не напряму.
- **Облікові дані:** `--token` / `--token-file` (`-` — stdin) і `--url` → `CF_TOKEN` / `CF_URL` → контекст `--context` / `CF_CONTEXT` → поточний контекст у `$XDG_CONFIG_HOME/container-forest/config.json` (інакше `~/.config/…`, на Windows `%APPDATA%`; каталог 0700, файл 0600, запис атомарний). Контексти дозволяють працювати з кількома інсталяціями. `forest logout` відкликає токен на сервері (`DELETE /api/me/tokens/current`) і забуває його.
- CLI не змінює пароль, passkeys, токени й прив'язку Discord: це вміє лише сесія в панелі (ADR-0007).

## Наслідки

- Будь-який спосіб входу в панель автоматично працює й для CLI: CLI не знає про паролі, passkeys чи Discord.
- Нова група ендпоінтів без автентифікації (`/api/cli/authorizations`, `/api/cli/token`) — вперше з лімітом запитів у ЦА.
- Сторінки `/cli/authorize` і `/cli/device` у панелі; перша — звичайний маршрут під входом, тож після логіну людина повертається на неї з тим самим кодом.
