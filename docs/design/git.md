# Git і підключення до git-серверів

Рішення — [ADR-0006](../adr/0006-git-connections.md). Шляхи `Domain/…`, `Application/…`, `Infrastructure/…`, `Api/…` — відносно `src/Aggregator`, шляхи панелі (`src/features/…`, `src/components/…`) — відносно `src/Web`.

- `IGitSource` — два виклики: `FetchAsync` повертає коміт гілки, `ReadAsync` читає каталог compose-файлу з нього. `GitFetchStep` записує коміт у деплой між ними, тож деплой, що впав на файлах (немає каталогу, перевищено ліміт пакета), усе одно показує свій коміт.
- Git: bare-клон на кожен репозиторій у `Git:CacheDirectory` (типово `git-cache` у робочому каталозі), fetch лише гілки стеку з `Prune`, файли читаються з дерева коміту без checkout. У пакет іде каталог compose-файлу (для compose в корені — увесь репозиторій) у межах `Deployments:MaxBundleBytes` (3 MiB); символьні посилання й сабмодулі пропускаються з попередженням.
- **Підключення до git-серверів і репозиторії** (ADR-0006). `GitConnection` (таблиці `GitConnections`, `GitConnectionEnvironments`): назва (унікальна), префікс адреси, необов'язковий токен (`ISecretProtector`, `SecretPurpose.GitAccessToken`, ніколи не повертається, `hasAccessToken`) з ім'ям користувача (типово `x-access-token`), дозволені середовища або «усі», секрет webhook організації. Керує лише адміністратор (`GitConnectionService`, `/api/git-connections/*`); редактор бачить підключення своїх середовищ, і лише свої середовища в `environmentIds`. Префікс не може лишити поза собою репозиторії підключення (409), хост при заданому токені не змінюється (400), підключення з репозиторіями не видаляється (409, FK `Restrict`). `GitRepository` має URL і необов'язковий `ConnectionId` (без нього — публічний, доступний усім середовищам); URL — під префіксом (`GitUrl.Covers`: хост і порт, сегменти шляху без урахування регістру й з відкиданням `.git`; `GitUrl.Parse` відхиляє облікові дані, query, fragment і будь-яке `%`-кодування в шляху, бо закодоване `..` чи `/` обійшло б префікс). Назви репозиторіїв не унікальні. Правила (`RepositoryAccess`): «редакторські середовища» — де користувач Editor на середовищі чи на стеку (`AccessPolicy.EditorEnvironments`); додати репозиторій може адміністратор або редактор, якщо підключення дозволене в одному з його середовищ (публічний — будь-який редактор); змінити репозиторій і його webhook — адміністратор або той, хто має `Permission.Deploy` на кожному стеку репозиторію (`RepositoryResponse.canManage`); недоступне підключення чи репозиторій — 404. `GitFetchStep` перевіряє `IsUsableIn` до fetch і передає `GitAccess` (токен підключення з `Scope` = префікс; `IsTrustedHost` для репозиторіїв підключення). `LibGit2SharpGitSource.CredentialsFor` віддає токен лише по HTTPS на адреси під префіксом. Для репозиторію без підключення `GitHostGuard` резолвить хост і відмовляє на loopback, приватних, CGNAT, link-local (metadata хмари), multicast адресах, якщо не задано `Git:AllowPrivateHosts`; помилка fetch такого репозиторію в лозі деплою узагальнена, деталі libgit2 — у лозі ЦА. Клон більший за `Git:MaxCacheBytes` (1 GiB) видаляється, деплой падає. Міграції: `GitConnections` (схема), `MoveRepositoryTokensToConnections` (кожен репозиторій з токеном отримує власне підключення з тим самим id, префіксом — своїм URL і середовищами своїх стеків), `RemoveRepositoryAccessTokens`; дві з них перебудовують таблицю `Repositories` у SQLite поза транзакцією (попередження EF при старті).
- LibGit2Sharp з NuGet не підтримує SSH — лише HTTPS.
