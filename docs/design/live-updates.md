# Live-оновлення

Клієнт — [src/Web/CLAUDE.md](../../src/Web/CLAUDE.md). Шляхи `Domain/…`, `Application/…`, `Infrastructure/…`, `Api/…` — відносно `src/Aggregator`, шляхи панелі (`src/features/…`, `src/components/…`) — відносно `src/Web`.

- **Live-оновлення** (`/hubs/live`, `LiveHub : Hub<ILiveClient>`, контракт — `ILiveClient` у `Api/Live/LiveHub.cs`, TS-типи — `src/Web/src/features/live/model.ts`): події несуть лише id (`EnvironmentsChanged()`, `ContainersChanged(env)`, `StackChanged(env, stack)`, `DeploymentChanged(env, stack, deployment)`), панель перечитує дані через API з його перевіркою прав. Хаб вимагає автентифікації (`RequireAuthorization`, `CloseOnAuthenticationExpiration`); з'єднання входить у групу `environment:<id>` кожного видимого середовища (`EnvironmentService.ListVisibleAsync`), тож id чужих стеків і деплоїв до нього не доходять; `EnvironmentsChanged` іде всім, і панель відповідає `Resubscribe` (ролі могли змінитися). Користувач стеку, а не середовища, у групі середовища бачить id інших його стеків і деплоїв (без назв) — свідомий компроміс. У хабі немає поточного HTTP-запиту, тому `IHttpContextAccessor` порожній: `LiveHub` передає `Context.User` у `ClaimsCurrentUser.Use` перед зверненням до сервісів.
- Сервіси live-оновлень не викликають: їх публікує інфраструктура через порт `ILiveUpdates` (`SignalRLiveUpdates`; без Api — `NullLiveUpdates`). `AggregatorDbContext.SaveChangesAsync` збирає зміни з трекера до збереження (`LiveChanges`: середовища й призначення ролей → `EnvironmentsChanged`, стеки, деплої й рядки їхнього логу) і публікує після успішного. `GrpcAgentChannel` після команд, що змінюють контейнери (start/stop/restart, деплой, restart/down стеку), публікує `ContainersChanged` і при помилці агента (compose міг змінити частину), але не для офлайн-агента. Помилка надсилання лише логується. Новий запис у БД, що має бути видно наживо, — новий випадок у `LiveChanges.Collect`.
