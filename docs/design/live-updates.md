# Live updates

The client side: [src/Web/CLAUDE.md](../../src/Web/CLAUDE.md). Paths `Domain/…`, `Application/…`, `Infrastructure/…`, `Api/…` are relative to `src/Aggregator`; panel paths (`src/features/…`, `src/components/…`) are relative to `src/Web`.

- **Live updates** (`/hubs/live`, `LiveHub : Hub<ILiveClient>`, the contract is `ILiveClient` in `Api/Live/LiveHub.cs`, the TS types are in `src/Web/src/features/live/model.ts`): events carry only ids (`EnvironmentsChanged()`, `ContainersChanged(env)`, `StackChanged(env, stack)`, `DeploymentChanged(env, stack, deployment)`), and the panel rereads the data through the API with its permission checks. The hub requires authentication (`RequireAuthorization`, `CloseOnAuthenticationExpiration`); a connection joins the `environment:<id>` group of every visible environment (`EnvironmentService.ListVisibleAsync`), so ids of other people's stacks and deployments never reach it. `EnvironmentsChanged` goes to everyone, and the panel answers with `Resubscribe` (roles may have changed). A user with a role on a stack, not the environment, sees in the environment's group the ids (not the names) of its other stacks and deployments: a deliberate trade-off. A hub call has no current HTTP request, so `IHttpContextAccessor` is empty: `LiveHub` passes `Context.User` to `ClaimsCurrentUser.Use` before calling services.
- Services don't publish live updates: the infrastructure does, through the `ILiveUpdates` port (`SignalRLiveUpdates`; without Api, `NullLiveUpdates`). `AggregatorDbContext.SaveChangesAsync` collects changes from the change tracker before saving (`LiveChanges`: environments and role assignments → `EnvironmentsChanged`, stacks, deployments and their log lines) and publishes them after a successful save. After commands that change containers (start/stop/restart, deploy, stack restart/down), `GrpcAgentChannel` publishes `ContainersChanged`, also when the agent fails (compose may have changed part of the stack), but not for an offline agent. A failed send is only logged. A new database record that must be visible live is a new case in `LiveChanges.Collect`.
- **Tests:** the test server has no real WebSocket, so the integration tests connect through long polling (the test server's `HttpMessageHandlerFactory`).
