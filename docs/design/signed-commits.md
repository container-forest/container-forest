# Підписи комітів

Рішення — [ADR-0011](../adr/0011-signed-commits.md). Шляхи `Domain/…`, `Application/…`, `Infrastructure/…`, `Api/…` — відносно `src/Aggregator`, шляхи панелі (`src/features/…`, `src/components/…`) — відносно `src/Web`.

- **Підписи комітів** (ADR-0011, `Domain/Access/SigningKey.cs`, `SshKeys.cs`, `Application/Deployments/Steps/VerifyCommitStep.cs`, `SigningKeyService`, `Api/Contracts/SigningKeyContracts.cs`).
  - `SigningKey` (таблиці `SigningKeys`, `SigningKeyEnvironments`): публічний SSH-ключ користувача (`ssh-ed25519`, ecdsa nistp256/384/521, FIDO `sk-…`, `ssh-rsa` від 2048 біт; `SshPublicKey.Parse` перевіряє структуру блоба), відбиток SHA256 унікальний на всю систему, до 20 на користувача. Область — `IsRestricted` + середовища (каскад, як у токенів), `Scope` — `AccessScope` без лише-читання. `AddedBy` — хто додав: свої ключі — лише сесія (`GetSignedInUserAsync`), адміністратор додає ключ іншому (службовий `ci`) і бачить/видаляє будь-чий; `AddedByAdministrator` показується поруч із підписом. Аудит: `SigningKeyAdded/Changed/Removed` (розширення області — з позначкою), `StackEndorsementChanged`.
  - Опції стеку `RequireSignedCommits`, `RequireImageDigests` (типово вимкнені; Editor; для системного стеку — 409; `PUT /api/stacks/{id}/require-signed-commits|require-image-digests`). `ValidateComposeStep` з `RequireImageDigests` відхиляє образ без digest, зі змінними та з `extends` без власного `image`.
  - `VerifyCommitStep` (після `GitFetchStep`, до `SopsDecryptStep`): підпис коміту — `ICommitInspector.ReadSignatureAsync` (`Commit.ExtractSignature` LibGit2Sharp; підписані дані — UTF-8 рядок, тож коміт в іншому кодуванні просто не перевіриться); `SshSignature.TryParse` (SSHSIG, namespace `git`) дає ключ → пошук за відбитком → `ICommitSignatureVerifier` (`SshKeygenSignatureVerifier`: `ssh-keygen -Y verify -n git` через `CliProcess`, `allowed_signers` лише з цим ключем у тимчасовому каталозі, `Signatures:SshKeygenPath`, `Signatures:Timeout`) **до** перевірки прав, щоб підроблений підпис не назвав власника → власник активний і `AccessPolicy.CanPerform(new Actor(owner, key.Scope), …)` на момент деплою. Автоматичні тригери (`Deployment.IsAutomatic`: webhook, хук) — ще й `ICommitInspector.DescendsFromAsync` від `DeployedCommit` (merge base), інакше `NotDescendant`; ручний — лише попередження. Rehydrate коміту, рівного `DeployedCommit`, — `AlreadyDeployed` без перевірки.
  - Непідписаний коміт — `DeployRequest.approveCommit` (повний SHA, `Deployment.ApprovedCommit`): деплоїться, лише якщо голова гілки — саме він (`ApprovedUnsigned`, причина зберігається), інакше `ApprovalOutdated`. Бот підтверджувати не вміє. Результат — `Deployment.Endorsement`, `EndorsementProblem`, `SignedBy` + `SignerName` (ім'я на той момент, без FK), `SigningKeyFingerprint`; у відповідях — `EndorsementResponse`. Тести зі справжнім `ssh-keygen` (`LibGit2SharpGitSourceTests`) без нього пропускаються, у CI (`CF_TEST_REQUIRE_SSH_KEYGEN=1`) падають; API-тести підміняють перевірку `StubCommits`.
