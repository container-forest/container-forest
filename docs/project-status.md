# Стан реалізації

Перелік реалізованого за компонентами. Етап, експлуатація й те, чого ще немає, — у [CLAUDE.md](../CLAUDE.md).

- **ЦА:** доменна модель, EF Core + SQLite, gRPC-шлюз агентів і бота (прив'язка Discord-акаунта за кодом, середовища, контейнери, start/stop/restart), команди контейнерів з авторизацією (`AuthorizedCommand`), `ICurrentUser` і фільтрація за видимістю, `/api/me`, вхід за паролем (ASP.NET Identity, cookie `cf_session`, `/api/auth/*`, перший адміністратор із `CF_BOOTSTRAP__*`), керування користувачами й ролями `/api/users/*`, пайплайн деплою з git-репозиторію (публічного або приватного через підключення до git-сервера, ADR-0006), вручну, за push-webhook GitHub, Gitea/Forgejo чи GitLab або за хуком деплою з CI, з розшифруванням секретів SOPS ключами середовища і їх автоматичним відновленням після перезавантаження хоста, логом та історією деплоїв, restart і down розгорнутого стеку (`StackCommandService`); креди registry на середовищі, зашифровані Data Protection (ADR-0003). API панелі для середовищ, контейнерів і їхніх логів (`/api/environments/*`), репозиторіїв, стеків і деплоїв (`/api/repositories`, `/api/stacks/*`, `/api/deployments/*`), а також для адміністраторів — створення й зміна середовищ, enrollment-токени, відкликання агента (`revoke-agent` забуває облікові дані й обриває з'єднання), креди registry й age-ключі середовищ (`/api/environments/{id}/age-keys`). Персональні API-токени з обмеженнями для CLI й скриптів (`Authorization: Bearer`, ADR-0007). Розшифрування й шифрування SOPS для git-фільтра CLI (`/api/sops/*`, прапорець `secrets` на токені, ADR-0010). Вхід без пароля з passkey і вхід та прив'язка Discord-акаунта через Discord OAuth2 (ADR-0009). Журнал аудиту (`/api/audit`, лише адміністратори): входи, користувачі й ролі, токени й ключі підпису, середовища, стеки, деплої, дії з контейнерами, розшифрування секретів, з відмовленими й невдалими спробами. Засвідчення вмісту стеку підписами SSH комітів: ключі підпису користувачів з обмеженням середовищами (`/api/me/signing-keys`, `/api/users/{id}/signing-keys`), опції стеку `RequireSignedCommits` і `RequireImageDigests`, підтвердження непідписаного коміту за SHA (ADR-0011). Ізоляція стеків на хості (ADR-0012): роль «адміністратор середовища» з делегованим адмініструванням середовища, політика compose середовища (Off/Audit/Enforce) за нормалізованою моделлю від агента з винятками середовища й стеку та звітом, ключі SOPS окремого стеку. У `Development` поруч із cookie діє dev-автентифікація `X-Dev-User`.
- **Агент:** рендеринг стеку для політики compose (`RenderStack` → `docker compose config` у tmpfs) і перевірка символьних посилань у джерелах bind-mount'ів перед `up`; реєстрація, з'єднання з heartbeat і перепідключенням, `ListContainers`, start/stop/restart і читання логів контейнера (`StreamContainerLogs` без `follow`) через Docker.DotNet.Enhanced, обробники `DeployStack`, `RestartStack`, `DownStack` через `docker compose` (креди registry — тимчасовий `DOCKER_CONFIG`), Docker-образ із docker CLI і compose-плагіном, скасування команд за `CancelRequest` (ЦА надсилає його, коли перестає чекати результат), події контейнерів (`ContainerEvent`) з потоку подій Docker. Файли стеку пишуться на місці за маніфестом (ADR-0004); деплой перевірено вживу на `example-voting-app`.
- **CLI `forest`** (`src/Cli`, ADR-0008): вхід через браузер або `--device`, `--with-token`; контексти; середовища (з ключами й кредами registry), контейнери з логами (`-f`), стеки (deploy зі стеженням, restart, down, джерело, перемикачі, хук деплою), деплої, репозиторії й webhook-и, підключення до git-серверів, користувачі з ролями, токенами й ключами підпису, канали, правила й історія сповіщень; секрети в git через git-фільтр (`forest secrets`, `forest git setup|teardown`, ADR-0010); політика compose й ролі середовища (`forest env policy show|set|report`, `forest stack policy allow|disallow`, `forest env role …`, `forest env key create --stack`, правила `<шлях>=<середовище>/<стек>`, ADR-0012). Бінарники для linux x64/arm64, macOS arm64 і Windows x64 публікує workflow `CLI` за тегом `cli-v<версія>`. CLI не вміє лише того, що потребує сесії в панелі: пароль, passkeys, власні токени й ключі підпису, прив'язка Discord.
- **Бот:** клієнт ЦА по gRPC (`IForestClient` → `GrpcForestClient`); slash-команди `/environments`, `/containers`, `/start`, `/stop`, `/restart`, `/stacks`, `/stack-restart`, `/stack-down`, `/link` на Discord.Net з автодоповненням; меню `/dashboard` на Components V2 (середовища → стеки → redeploy, redeploy with pull, restart, down); усі відповіді ephemeral; Docker-образ (`src/DiscordBot/Dockerfile`) і приклад розгортання `deploy/discord-bot/compose.yaml`; сповіщення в Discord-каналах (потік `WatchNotifications`: деплої, падіння й unhealthy контейнерів, агент офлайн/онлайн) з кнопками «Restart» і «Logs» під упалим контейнером.
