# Implementation status

What's implemented, by component. Version, production use and what's still missing: [CLAUDE.md](../CLAUDE.md).

- **Aggregator:** the domain model, EF Core + SQLite, the gRPC gateway for agents and the bot (Discord account linking by code, environments, containers, start/stop/restart), authorized container commands (`AuthorizedCommand`), `ICurrentUser` and filtering by visibility, `/api/me`, password sign-in (ASP.NET Identity, the `cf_session` cookie, `/api/auth/*`, the first administrator from `CF_BOOTSTRAP__*`), user and role management `/api/users/*`, the deployment pipeline from a git repository (public, or private through a git connection, ADR-0006), triggered by hand, by a GitHub, Gitea/Forgejo or GitLab push webhook or by a CI deploy hook, with SOPS secrets decrypted with the environment's keys and restored automatically after a host reboot, a deployment log and history, restart and down of a deployed stack (`StackCommandService`); unmanaged stacks, i.e. compose projects started by hand on a host, with pull, up, restart and down (`UnmanagedStackService`, ADR-0016), and removing a stopped container; registry credentials per environment, encrypted with Data Protection (ADR-0003). The panel's API for environments, containers and their logs (`/api/environments/*`), repositories, stacks and deployments (`/api/repositories`, `/api/stacks/*`, `/api/deployments/*`), and for administrators: creating and changing environments, enrollment tokens, revoking an agent (`revoke-agent` forgets its credentials and drops the connection), registry credentials and environment age keys (`/api/environments/{id}/age-keys`). Personal API tokens with restrictions for the CLI and scripts (`Authorization: Bearer`, ADR-0007). SOPS decryption and encryption for the CLI's git filter (`/api/sops/*`, the `secrets` flag on a token, ADR-0010). Passwordless sign-in with passkeys, and sign-in and account linking with Discord OAuth2 (ADR-0009). The audit log (`/api/audit`, administrators only): sign-ins, users and roles, tokens and signing keys, environments, stacks, deployments, container actions, secret decryption, including denied and failed attempts. Endorsing stack content with SSH commit signatures: users' signing keys restricted to environments (`/api/me/signing-keys`, `/api/users/{id}/signing-keys`), the stack options `RequireSignedCommits` and `RequireImageDigests`, approving an unsigned commit by SHA (ADR-0011). Stack isolation on the host (ADR-0012): the environment administrator role with delegated administration, the environment's compose policy (Off/Audit/Enforce) checked against the agent's normalised model, with environment and stack allowances and a report, SOPS keys for a single stack. System settings as typed sections, with environment variables taking precedence and identity confirmation for sensitive changes (ADR-0013). Image updates by the aggregator (ADR-0015): image policies on a stack, registry polling and an image hook for CI, committing the new tag signed with the aggregator's key and endorsed by an update record, pinning and rolling back a tag, a write token on the connection. An optional backup of the database and the key ring, encrypted to an offline key, to an S3-compatible bucket, on a schedule and by hand (`/api/settings/backup`, `/api/backup`, ADR-0014). In `Development`, the `X-Dev-User` dev authentication works alongside the cookie.
- **Agent:** rendering a stack for the compose policy (`RenderStack` → `docker compose config` in tmpfs) and checking bind-mount sources for symbolic links before `up`; enrollment, the connection with heartbeats and reconnects, `ListContainers`, start/stop/restart and reading container logs (`StreamContainerLogs` without `follow`) through Docker.DotNet.Enhanced, the `DeployStack`, `RestartStack` and `DownStack` handlers through `docker compose`, finding unmanaged stacks in `Agent:UnmanagedStackRoots` and `ListUnmanagedStacks`/`ControlUnmanagedStack`, `RemoveContainer` (registry credentials in a temporary `DOCKER_CONFIG`), a Docker image with the docker CLI and the compose plugin, cancelling commands on `CancelRequest` (the aggregator sends it when it stops waiting for a result), container events (`ContainerEvent`) from Docker's event stream. Stack files are written in place using a manifest (ADR-0004); deployment was checked live on `example-voting-app`.
- **CLI `forest`** (`src/Cli`, ADR-0008): sign-in through the browser or `--device`, `--with-token`; contexts; environments (with keys and registry credentials), containers with logs (`-f`) and removal, unmanaged stacks (`forest unmanaged list|up|pull|restart|down`), stacks (deploy with following, restart, down, source, toggles, the deploy hook), deployments, repositories and webhooks, git connections, users with roles, tokens and signing keys, notification channels, rules and history; secrets in git through the git filter (`forest secrets`, `forest git setup|teardown`, ADR-0010); the compose policy and environment roles (`forest env policy show|set|report`, `forest stack policy allow|disallow`, `forest env role …`, `forest env key create --stack`, rules `<path>=<environment>/<stack>`, ADR-0012); backup status and runs (`forest backup status|run`, ADR-0014); image policies and the image hook (`forest stack image-policy …`, `forest stack image-hook …`), a connection's write token, the aggregator's signing key (`forest system signing-key show|rotate`, ADR-0015). Binaries for linux x64/arm64, macOS arm64 and Windows x64 are attached to every system release (release-please, tag `vX.Y.Z`). The CLI can't do only what needs a panel session: your password, passkeys, your own tokens and signing keys, Discord linking, system settings.
- **Bot:** the aggregator's gRPC client (`IForestClient` → `GrpcForestClient`); the slash commands `/environments`, `/containers`, `/start`, `/stop`, `/restart`, `/remove`, `/stacks`, `/stack-restart`, `/stack-down`, `/stack-up`, `/stack-pull` (the last two for unmanaged stacks, which `/stacks` shows next to managed ones) and `/link` on Discord.Net with autocomplete; the `/dashboard` menu on Components V2 (environments → stacks → redeploy, redeploy with pull, restart, down); every reply ephemeral; a Docker image (`src/DiscordBot/Dockerfile`) and the deployment example `deploy/discord-bot/compose.yaml`; notifications in Discord channels (the `WatchNotifications` stream: deployments, crashed and unhealthy containers, agents going offline and online) with *Restart* and *Logs* buttons under a crashed container.
