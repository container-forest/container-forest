# CLI `forest`: conventions

CLI sign-in: [docs/design/auth.md](../../docs/design/auth.md); the git filter: [docs/design/secrets.md](../../docs/design/secrets.md).

- `src/Cli`, binary `forest`, NativeAOT (`PublishAot`, `InvariantGlobalization`). `dotnet publish src/Cli -r linux-x64 -c Release` publishes without trimming warnings and must stay that way (System.Text.Json only with source generation, no reflection).
- Kiota generates the API client into `src/Cli/Api/Generated` (`scripts/generate-cli-client.sh`, the tool is in `dotnet-tools.json`). Generated files are committed and never edited by hand; CI regenerates and compares them. Changed the aggregator's API: rebuild `Api`, run the script, commit. Endpoints the CLI doesn't call are excluded in the script.
- Commands never call the generated client directly, only through the `ForestApi` adapter (`src/Cli/Api/ForestApi*.cs`): it returns lists instead of null and turns missing required fields into `CliException`. `ForestApiFactory` builds the `HttpClient` from Kiota's handlers **without `RetryHandler`** (retrying a POST would deploy twice) and with `ProblemDetailsHandler`, which turns any failed response into a `ServerProblemException` carrying the aggregator's `title`/`detail`. `BearerAuthenticationProvider` adds the token only to requests to the connection's server.
- Credentials (`CredentialResolver`): `--url` > `CF_URL` > context; `--token` > `--token-file` (`-` is stdin) > `CF_TOKEN` > the context's token; the context is `--context` > `CF_CONTEXT` > the current one. A context's token goes only to that context's server (`ServerUrl.SameServer`), never to a different `--url`. `ServerUrl.Parse`: no scheme means https; `http://` only for loopback. Configuration is `ConfigStore` (`$XDG_CONFIG_HOME/container-forest/config.json`, else `~/.config/…`, `%APPDATA%` on Windows; directory 0700, file 0600 from creation, written through a temporary file and `File.Move`).
- A command derives from `ForestCommand` (Template Method: `Configure` adds arguments, `ExecuteAsync` does the work; `CliHost.RunAsync` resolves credentials and turns `CliException`, `ServerProblemException`, `ApiException` and `HttpRequestException` into `forest: <message>` on stderr and an `ExitCodes` exit code). Commands in an environment derive from `EnvironmentCommand` (`--env`/`-e`, else the context's default environment, else the only visible one), commands about a stack from `StackCommand`; groups are `CommandGroup` (Composite, `ICliNode`). The tree is `ForestCli.Build`. Results go to stdout (a `Table`, or `-o json` through `KiotaJsonSerializer`), progress and notes to stderr (`CliOutput.Note`), secrets shown once on their own line in stdout (`CliOutput.Secret`). Destructive actions require `--yes` (`Confirmation`). Passwords (registry credentials) come only from stdin, never from an option.
- Sign-in (`BrowserLogin`): `StartLoginAsync` → a loopback `LoopbackSignal` on `127.0.0.1:0` (TcpListener, answers `/done`) → the browser through `IBrowser` (`SystemBrowser`, shell execute) → polling at the server's interval, `SlowDown` adds 5 s; the browser's signal wakes polling at once (after the decision the aggregator doesn't answer `SlowDown`). `--device` skips the loopback and the browser. Signing in to the same context again revokes the previous token.
- Passwords and tokens for commands (`user create`, `user reset-password`, `connection add --with-token`, `connection set-token`, `env registry set`) come through `SecretInput`: from stdin, or typed without echo in a terminal (`CliHost.InteractiveTerminal`); never from an option. A command-line parse error exits with code 2 (`Program.Main` overrides System.CommandLine's 1).
  - The filter's stdout carries only the protocol: `CliHost.StandardInput`/`StandardOutput` are byte streams, notes go to stderr. Git commands go through `GitWorkTree` (a `git` process without a shell).
- The `CLI` workflow (`.github/workflows/cli.yml`): on a PR that changes the CLI, an AOT build for linux-x64; on a release (called by the `Release` workflow with the `vX.Y.Z` tag) and by hand, linux-x64, linux-arm64, osx-arm64 and win-x64 (the `platforms` job picks the matrix), and the binaries and `SHA256SUMS` are attached to the GitHub Release. The version is the system's shared version from `Directory.Build.props` ([Releases](../../docs/development.md#releases)); the CLI project has no `<Version>` of its own.
- Tests: `tests/Cli` (command-line parsing, credentials, configuration and file permissions, tables, logs, loopback); end to end, `tests/Aggregator/Api/CliEndToEndTests.cs` (the CLI against an in-memory aggregator with a fake agent and a "browser" that approves the sign-in). That's why `CliHost` takes streams, environment variables, the configuration directory, an HTTP handler and a browser; `InternalsVisibleTo` covers both test projects. The entry point is an explicit `ContainerForest.Cli.Program` (a global `Program` would clash with the aggregator's in tests).
