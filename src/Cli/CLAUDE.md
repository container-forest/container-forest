# CLI `forest`: конвенції

Вхід у CLI — [docs/design/auth.md](../../docs/design/auth.md), git-фільтр — [docs/design/secrets.md](../../docs/design/secrets.md).

- `src/Cli`, бінарник `forest`, NativeAOT (`PublishAot`, `InvariantGlobalization`); публікація — `dotnet publish src/Cli -r linux-x64 -c Release` без попереджень обрізання, і так має лишатися (System.Text.Json лише з source generation, без рефлексії).
- Клієнт API генерує Kiota в `src/Cli/Api/Generated` (`scripts/generate-cli-client.sh`, інструмент у `dotnet-tools.json`); згенеровані файли комітяться й руками не правляться; CI перегенеровує й порівнює. Змінив API ЦА — перезбери `Api`, запусти скрипт, закомить. Ендпоінти, яких CLI не викликає, виключені в скрипті.
- Команди не звертаються до згенерованого клієнта напряму, лише через адаптер `ForestApi` (`src/Cli/Api/ForestApi*.cs`): він повертає списки замість null і перетворює відсутні обов'язкові поля на `CliException`. `ForestApiFactory` збирає `HttpClient` з обробників Kiota **без `RetryHandler`** (повтор POST поставив би деплой удруге) і з `ProblemDetailsHandler`, що робить з будь-якої невдалої відповіді `ServerProblemException` з `title`/`detail` ЦА. `BearerAuthenticationProvider` додає токен лише до запитів на сервер з'єднання.
- Облікові дані (`CredentialResolver`): `--url` > `CF_URL` > контекст; `--token` > `--token-file` (`-` — stdin) > `CF_TOKEN` > токен контексту; контекст — `--context` > `CF_CONTEXT` > поточний. Токен контексту йде лише на сервер контексту (`ServerUrl.SameServer`), не на чужий `--url`. `ServerUrl.Parse`: без схеми — https; `http://` лише для loopback. Конфігурація — `ConfigStore` (`$XDG_CONFIG_HOME/container-forest/config.json`, інакше `~/.config/…`, на Windows `%APPDATA%`; каталог 0700, файл 0600 із створення, запис через тимчасовий файл і `File.Move`).
- Команда — нащадок `ForestCommand` (Template Method: `Configure` додає аргументи, `ExecuteAsync` працює; `CliHost.RunAsync` розв'язує облікові дані й перекладає `CliException`, `ServerProblemException`, `ApiException`, `HttpRequestException` у `forest: <повідомлення>` на stderr і код виходу `ExitCodes`). Команди в середовищі — `EnvironmentCommand` (`--env`/`-e`, інакше типове середовище контексту, інакше єдине видиме), про стек — `StackCommand`; групи — `CommandGroup` (Composite, `ICliNode`). Дерево — `ForestCli.Build`. Результат — stdout (таблиця `Table` або `-o json` через `KiotaJsonSerializer`), хід і примітки — stderr (`CliOutput.Note`), секрети, показані один раз, — окремим рядком у stdout (`CliOutput.Secret`). Руйнівні дії вимагають `--yes` (`Confirmation`). Паролі (креди registry) — лише зі stdin, не опцією.
- Вхід (`BrowserLogin`): `StartLoginAsync` → loopback `LoopbackSignal` на `127.0.0.1:0` (TcpListener, відповідає на `/done`) → браузер через `IBrowser` (`SystemBrowser`, shell execute) → опитування з інтервалом сервера, `SlowDown` додає 5 с; сигнал із браузера будить опитування одразу (після рішення ЦА не відповідає `SlowDown`). `--device` — без loopback і браузера. Повторний вхід у той самий контекст відкликає попередній токен.
- Паролі й токени для команд (`user create`, `user reset-password`, `connection add --with-token`, `connection set-token`, `env registry set`) — `SecretInput`: зі stdin, а в терміналі (`CliHost.InteractiveTerminal`) — введення без відлуння; ніколи не опцією. Помилка розбору командного рядка — код 2 (`Program.Main` перекриває 1 від System.CommandLine).
  - stdout фільтра — лише протокол: `CliHost.StandardInput`/`StandardOutput` — байтові потоки, примітки — у stderr. Git-команди — `GitWorkTree` (процес `git` без shell).
- Workflow `CLI` (`.github/workflows/cli.yml`): на PR, що змінює CLI, — AOT-збірка linux-x64; на реліз (його викликає workflow `Release` з тегом `vX.Y.Z`) і вручну — linux-x64, linux-arm64, osx-arm64, win-x64 (матрицю обирає job `platforms`), а бінарники й `SHA256SUMS` додаються до GitHub Release. Версія — спільна версія системи з `Directory.Build.props` ([Релізи](../../CONTRIBUTING.md#релізи)); власного `<Version>` у проєкті CLI немає.
- Тести: `tests/Cli` (розбір командного рядка, облікові дані, конфігурація й права файлу, таблиця, логи, loopback); наскрізні — `tests/Aggregator/Api/CliEndToEndTests.cs` (CLI проти ЦА в пам'яті з фейковим агентом і «браузером», що підтверджує вхід). `CliHost` приймає потоки, змінні середовища, каталог конфігурації, HTTP-обробник і браузер саме для цього; `InternalsVisibleTo` — для обох тестових проєктів. Точка входу — явний `ContainerForest.Cli.Program` (глобальний `Program` конфліктував би з ЦА в тестах).
