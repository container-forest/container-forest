# Discord bot: conventions

The contract with the aggregator, the token, account linking and `/dashboard`: [docs/design/discord-bot.md](../../docs/design/discord-bot.md); the notification stream and its buttons: [docs/design/notifications.md](../../docs/design/notifications.md).

- The bot reaches the aggregator only through `IForestClient` (`src/DiscordBot/Forest`). Errors derive from `ForestException`, and their text is shown to the user. An unreachable aggregator and `invalid-bot-token` are `ForestUnavailableException`: logged, with a generic message for the user. A status created by the gRPC client itself (it has a `Status.DebugException`) means the call never reached the aggregator, even if the code is `Unavailable` or `Internal`. The bot's tests generate the server side of `bot.proto` and reference the bot through `extern alias bot` so the generated types don't clash.
- Bot commands derive from `BotCommand<TArgs, TResult>` (`src/DiscordBot/Commands`): a template method of defer → call the aggregator → format → error as a reply. Discord.Net sees only the `ForestModule` module and the `DiscordInteraction` adapter (`ICommandInteraction`), so command logic is tested without Discord. Every reply is ephemeral: a deferred reply keeps the visibility it was deferred with, and lists of environments and containers mustn't reach a channel with people who have fewer rights. Replies are sent with `AllowedMentions.None`, and outside text is escaped (`Markdown.Escape`). Autocomplete can't be deferred: it has a 2 s budget, and an error means an empty list. `Development` registers commands on the test server (`CF_DISCORD__DEVGUILDID`, required); other environments register them globally.

## Library notes

Discord.Net pitfalls not covered in the design notes. Why the library was chosen: [docs/dependencies.md](../../docs/dependencies.md).

- `LoginAsync` checks only the token's format; a wrong token shows up as a 401 while connecting to the gateway, which Discord.Net retries forever. After login the bot makes a real request (`GetApplicationInfoAsync`), and a `Disconnected` with 401 or close code 4004 stops it with exit code 1 and a hint about `CF_DISCORD__TOKEN`.
- With `RunMode.Async`, command exceptions don't come back from `ExecuteCommandAsync`; they arrive in `InteractionExecuted`, where the bot logs them.
- Nothing can be posted before `Ready`: the guild and channel caches are empty until then. A channel from `GetChannelAsync` may not be a text channel: check for `IMessageChannel`.
- `HttpException.DiscordCode` carries Discord's JSON error code (10003 unknown channel, 50001 missing access, 50013 missing permissions). `DiscordErrorCode` member names aren't documented, so compare the numbers.
- Limits: an embed field value is up to 1024 characters. A Components V2 message (`IS_COMPONENTS_V2`) can't have `content` or embeds, holds up to 40 components including nested ones and 4000 characters of text; it can't be combined with embeds, so notification buttons use the old action-row components. A deferred slash-command reply switches to V2 by setting `MessageProperties.Flags` in `ModifyOriginalResponseAsync`.
- `custom_id` is up to 100 characters and must be unique within a message: GUIDs are base64url-encoded (22 characters), and disabled *Back*/*Next* buttons get their own dead-end ids. `[ComponentInteraction("dash:*")]` passes everything after the prefix, colons included. A test checks routing with `InteractionService.SearchComponentCommand`; `AddModuleAsync` validates the module's constructor dependencies, so register them in the test.
- `StackAutocompleteHandler` picks the action from `Data.CommandName`, so command names appear both in `[SlashCommand]` and in its `switch`: renaming a command without the handler silently widens the suggestions.
- gRPC reports a cancelled call as `RpcException(Cancelled)`, or another code when racing a broken stream: once the cancellation token has fired, the client turns any `RpcException` into `OperationCanceledException`.
- Name clashes: Discord.Net has its own `Discord.BotGateway` type (aliased in `DependencyInjection`), and the bot's Discord code lives in the `Interactions` namespace so it doesn't shadow `Discord`.
